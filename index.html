1
Basics

From computer to microprocessor

A microprocessor is a CPU on one chip. Add memory and I/O and it becomes a microcomputer.

  • Computer vs calculator: the computer runs a stored program; the calculator waits for each key.
  • Bit = 0/1 · Nibble = 4 bits · Byte = 8 bits · Word = bits the ALU handles at once.
  • Integration grew SSI → MSI → LSI → VLSI → SLSI until a whole CPU fitted on one chip.
  • Moore's Law (1965): transistors per chip double every 18–24 months.
  • Intel 4004 (15 Nov 1971): first commercial µP. 4-bit, 2,300 transistors, 108 kHz, 10 µm. Built for the Busicom calculator: MCS-4 = 4004 CPU + ROM + RAM + shift register (I/O).
  • 8086 (1978): 16-bit data, 20-bit address, 29,000 transistors. 8088 (1979): same inside, 8-bit external bus (IBM PC, 1981). 8051 (1980): microcontroller.

2
Architecture models

Von Neumann vs Harvard

Do instructions and data share one road or travel on two roads?

  • Von Neumann bottleneck: code and data compete for one memory path, so memory bandwidth limits speed.
  • Modified Harvard: one unified memory for software, but separate instruction and data caches inside the CPU (modern x86, ARM).
  • Architecture vs organization: architecture = what the programmer sees (instruction set, registers, addressing modes). Organization = how hardware builds it (bus widths, control signals, timing). 8086 and 8088: same architecture, different organization (16-bit vs 8-bit external data bus).
Hook: one road vs two roads. And never mix the axes: VN/Harvard is about memory, RISC/CISC is about instructions. 8086 = VN + CISC · 8051 = Harvard + CISC.

3
Inside the CPU

ALU, control unit, registers, and the fetch path

The control unit coordinates, the ALU calculates, the registers hold values. Every instruction goes Fetch → Decode → Execute → Store.

  • ALU: add, subtract, compare, AND/OR/XOR/NOT, shift; sets flags Z, C, S, O.
  • Control unit: fetches, decodes, generates control signals (register enables, ALU select, memory/I-O read-write). Coordinator, not calculator.
  • PC next instruction address (8086: IP) · IR instruction being decoded · MAR address sent to memory · MDR/MBR data from/to memory · SP top of stack · Flags status.
  • Clock: T = 1/f. One instruction cycle = several machine (bus) cycles = many T-states.

Hook: PC points, MAR asks, MDR receives, IR holds, CU decodes.

4
Memory & buses

Memory hierarchy, RAM/ROM, buses, tri-state, stack

Three buses join everything: address says where, data carries what, control says when and which operation.

  • RAM read/write, volatile: variables, stack. SRAM = flip-flops, fast, no refresh (cache). DRAM = capacitors, dense, needs refresh (main memory).
  • ROM non-volatile: boot code, firmware. Mask ROM → PROM (once) → EPROM (UV erase) → EEPROM/Flash (electrical erase).
  • Address bus: one-way out of CPU; N lines → 2N locations. 8086: A0–A19.
  • Data bus: two-way; width = bits per transfer. 8086: D0–D15.
  • Control bus: RD, WR, M/IO, READY, INTR…
  • Stack: LIFO. PUSH saves, POP restores; CALL saves the return address, RET restores it.

Why tri-state? Many devices share one data bus. Only the selected device drives it; all others sit in Z.

Bus contention = two devices drive the same line (one 1, one 0): wrong value, large current, heat, possible damage. Prevented by the address decoder (one CS at a time) and OE only during that device's read.

Hook: Address = where (one-way out) · Data = what (both ways) · Control = when. Only one talker on the bus; the rest are in Z.

5
Programming system

Instruction format, addressing modes, RISC/CISC, languages

An instruction = opcode (what to do) + operands (on what). Addressing modes are the rules for finding the operand.

Five instruction groups (Assignment 1, Q6)

  1. Data transfer: MOV, PUSH, POP, IN, OUT
  2. Arithmetic: ADD, SUB, INC, DEC, MUL, DIV
  3. Logical: AND, OR, XOR, NOT, shift, rotate
  4. Branch: JMP, JNZ, CALL, RET
  5. Machine control: NOP, HLT, STC, CLI

8086 also has string instructions (MOVSB); 8051 has bit instructions (SETB, JB) and no HLT.

Machine code decoded: MOV AL, 05H = B0 05

1011 · 0 · 000 · 0000 0101

1011 = move immediate to register · w = 0 byte · reg 000 = AL · data = 05H. 8051 equivalent MOV A,#05H = 74 05.

Directives (for the assembler, never executed)

ORG (start address) · DB byte · DW word · DD doubleword · EQU constant · END · MASM: SEGMENT, ENDS, ASSUME.

6
Microprocessor system

Decoding, I/O, transfer schemes, cache, pipelining

A microprocessor needs external ROM, RAM, I/O, clock, reset, and an address decoder that picks one chip at a time.

Address decoding

Upper address bits → decoder → exactly one CS. Lower bits → every chip, to pick the location inside it.

A15 A14ChipRange
0 0ROM0000–3FFFH
0 1RAM4000–7FFFH
1 0I/O8000–BFFFH
1 1noneC000–FFFFH

4A10H → A15A14 = 01 → RAM. Full exam version: Circuits → 74LS138.

I/O mapping

I/O-mapped: separate port space, IN/OUT, uses M/IO, no memory lost (8086: 64K ports). Memory-mapped: devices sit in the memory map, any MOV works, uses up memory addresses (8051 SFRs, MOVX).

Data transfer schemes (Assignment 2)

  1. Programmed I/O — CPU runs the transfer:
    • Synchronous: device as fast as CPU.
    • Asynchronous / handshake (polled): CPU keeps checking a ready flag.
    • Interrupt-driven: device interrupts when ready, CPU free meanwhile → best for a slow device.
  2. DMA: DMA controller (8237) takes the bus with HOLD/HLDA and moves memory ↔ I/O bypassing the CPU.

Speed-ups

  • Cache: small fast memory of recently used data (locality). Hit = found; miss = go to main memory.
  • Pipelining: overlap stages → more instructions finish per unit time. One instruction is not faster.
  • Prefetching: fetch next bytes early (8086 queue). The queue is not a cache.
  • Flush: a taken jump makes prefetched bytes wrong → clear queue, refill.

See it moving: Circuits → Pipeline and flush. Calculators: Practice.

Hook: slow device → interrupt · bulk transfer without CPU → DMA · CPU waiting for memory → cache, pipeline, prefetch.

7
8086 architecture

BIU + EU, registers, segmentation, flags

16-bit CPU, 20-bit address bus (1 MB), split into a Bus Interface Unit that fetches and an Execution Unit that executes, at the same time.

How they cooperate (8 steps)

  1. BIU fetches bytes from CS:IP.
  2. Puts them in the 6-byte queue.
  3. EU takes bytes from the front.
  4. EU decodes and executes.
  5. Memory operand needed → EU computes EA, asks BIU.
  6. BIU adds segment, runs the bus cycle, returns data.
  7. Meanwhile BIU keeps prefetching (when ≥ 2 bytes free and bus idle; queue full → no fetch).
  8. Taken jump → queue flushed, refill from new address.

Minimum vs maximum (one line)

Min (MN/MX = 1): 8086 alone makes every control signal. Support: 8284 clock, 3 × 8282 latches, 2 × 8286 transceivers.

Max (MN/MX = 0): with 8087/8089; the 8086 outputs S2 S1 S0 and the 8288 bus controller makes the commands. HOLD/HLDA become RQ/GT0, RQ/GT1.

Legal rules

  • Only BX, BP, SI, DI can point. [AX], [CX], [DX] are illegal.
  • Pairs: [BX+SI] [BX+DI] → DS · [BP+SI] [BP+DI] → SS. Never [BX+BP] or [SI+DI].
  • Override prefix: ES 26H, CS 2EH, SS 36H, DS 3EH. Cannot override: fetch (CS:IP), stack (SS:SP), string destination (ES:DI).
  • Little-endian: low byte at the lower address. MOV AX,1234H = B8 34 12.
  • Data transfer changes no flags (except SAHF, POPF).

10
8051

The 8051 microcontroller

8-bit, everything on one chip: 4 KB ROM, 128 B RAM, four ports, two timers, a UART, five interrupts.

  • A accumulator · B for MUL AB/DIV AB · R0–R7 in 4 banks (00–07H, 08–0FH, 10–17H, 18–1FH) · DPTR 16-bit pointer · PC 16-bit · SP 8-bit, 07H at reset, grows up · PSW CY AC F0 RS1 RS0 OV – P (no zero flag).
  • Internal RAM: banks 00–1FH, bit-addressable 20–2FH, general 30–7FH, SFRs 80–FFH.
  • Code read by MOVC, fetched with PSEN · external data by MOVX with RD/WR → separate spaces = Harvard-style.
  • P0 = low address/data (ALE latches), P2 = high address. UART on TXD P3.1 / RXD P3.0.
  • Clock: 12 oscillator periods per machine cycle (12 MHz → 1 µs).
Hook: 8051 = “4-128-4-2-1-5”: 4 KB ROM, 128 B RAM, 4 ports, 2 timers, 1 UART, 5 interrupts.

B · Bus cycle timing (T1–T4) — live

StateWhat happens
T1Address on AD0–AD15, A16–A19, BHE. ALE pulses and the latches grab it. DT/R set (0 read, 1 write).
T2Status replaces A16–A19. Read: AD bus floats (Z). Write: CPU drives data. RD or WR goes low; DEN goes low.
T3Data moves. READY sampled: if 0, Tw states are inserted after T3.
T4Read: CPU latches data. Write: memory stores as WR rises. RD/WR/DEN return high.

Read has a float (Z) period because the CPU must let go of AD lines for memory to drive them; in a write the CPU keeps driving. 8284A clock: crystal ÷ 3, 33% duty (high 1/3, low 2/3) — 15 MHz crystal → 5 MHz CLK → T = 200 ns.

C · Address decoding with the 74LS138 — live solver

Type the chip size and the start address of each chip. The solver builds the memory-map table and wires the decoder. Default = the exam question.

Method: (1) chip lines = log₂(size) → those go to every chip. (2) End = start + size − 1. (3) Write A19…A16 for each start. (4) Bits that change between chips → C B A (A = lowest). (5) Bits that stay fixed → enables: a fixed 1 → G1 (active high), a fixed 0 → G2A/G2B (active low). Unused G1 → Vcc, unused G2 → GND. (6) Output number = CBA value → that chip's CS.
